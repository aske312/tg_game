# Установка и управление сервером

Сервер получает приложение из последнего опубликованного стабильного [GitHub Release](https://github.com/aske312/tg_game/releases). Порядок выпуска описан в [RELEASING.md](../RELEASING.md).

## Установка

Нужны **Ubuntu 24.04+ или Debian 12+**, доступ root либо sudo, публичный домен или IP. Откройте TCP-порты **80**, **443** и **8443** для конструктора. Домен должен указывать на сервер.

Подключитесь по SSH и выполните:

```bash
sudo apt-get update
sudo apt-get install -y curl ca-certificates
curl -fsSL https://raw.githubusercontent.com/aske312/tg_game/main/deploy/install.sh -o /tmp/rat-race-install.sh
sudo bash /tmp/rat-race-install.sh
```

Установщик спросит адрес приложения, токен и имя Telegram-бота, email для HTTPS. Он настроит приложение, бота, конструктор и автоматический запуск после перезагрузки сервера.

- Только приложение и бот: добавьте `--app-only` к последней команде.
- Установка без вопросов: заполните приватный файл по [примеру](install.env.example), задайте ему права `600` и передайте `--config /root/rat-race-install.env`.
- Адрес и пароль нового конструктора: `sudo cat /etc/rat-race/builder-access.txt`.

Повторная установка сохраняет настройки, пароли и игры. На существующем сервере один раз запустите этот установщик, чтобы добавить новые команды управления. Установка и обновление перезапускают приложение — выполняйте их между играми. Если сервер уже обслуживает другие сайты, прокси нужно настроить отдельно.

Медиафайлы и материалы одной игры поддерживаются до 10 ГБ (10 × 1024³ байт). Обновление конструктора устанавливает новый лимит его прокси автоматически. Для загрузки файлов напрямую в комнату на ранее установленном сервере также замените `max_size 26MB` в `/etc/caddy/Caddyfile` на `max_size 10737418240`, проверьте конфигурацию командой `sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile` и примените её через `sudo systemctl reload caddy`. При использовании своего прокси задайте такой же или больший предел тела запроса. Публикация, игровые копии и экспорт используют диск; предусмотрите место для этих копий помимо исходных файлов.

## Обновление

Сначала подготовьте версию и опубликуйте релиз по [инструкции](../RELEASING.md). Одного коммита в `main` недостаточно:

```powershell
.\.venv\Scripts\python.exe scripts/release.py tag
```

Затем на сервере:

```bash
sudo rat-race update
```

Обновление получает тег опубликованного релиза, сверяет номер версии, запускает проверки, сохраняет копию базы и перезапускает службы. При ошибке запуска возвращает предыдущую версию. Отправка кода в GitHub сама по себе сервер не обновляет.

## Управление из конструктора

После входа нажмите **Настройки приложения** в шапке конструктора. Панель показывает загрузку процессора, использование памяти и диска, время работы сервера, состояние служб и версии игры и конструктора. Статистика обновляется каждые пять секунд, пока панель открыта.

**Обновить из GitHub** устанавливает последний опубликованный стабильный релиз для всех установленных компонентов. **Откатить версию** возвращает предыдущие установленные версии, показанные в панели. Перед запуском сохраняется несохранённый черновик и запрашивается подтверждение. Выполняйте операции между играми: службы перезапускаются. Журнал и результат операции доступны в панели; её закрытие не отменяет операцию.

При успешном переключении сохраняются указатели `current-previous` и `builder-current-previous`. Повторное обновление на тот же релиз их не заменяет. При сбое обновления или отката возвращаются исходные версии компонентов и прежние цели отката. Перед откатом игры создаётся копия базы. Игры, медиа и текущие данные сохраняются; откат кода автоматически не восстанавливает старую базу. Если новая версия меняет формат данных несовместимым образом, восстановление резервной копии нужно выполнять отдельно.

Панель работает через отдельную службу `rat-race-control.service`. Она устанавливается автоматически при первом обновлении на версию с этой возможностью через существующую SSH-команду `sudo rat-race update` (или `commands\server.cmd update`). Конструктор сохраняет ограничения своей службы и обращается к локальному Unix-сокету; выполнять произвольные команды через панель нельзя. Доступ к панели получают пользователи, вошедшие по паролю конструктора. На локальном Windows-запуске операции сервера недоступны.

Если откат возвращает конструктор, выпущенный до появления панели, перезагрузите страницу: эта версия не содержит настроек приложения. Повторное обновление доступно через SSH.

## Основные команды

| Команда | Действие |
| --- | --- |
| `sudo rat-race start` | Запустить |
| `sudo rat-race stop` | Остановить |
| `sudo rat-race restart` | Перезапустить |
| `sudo rat-race update` | Установить последний опубликованный релиз |
| `sudo rat-race rollback` | Вернуть предыдущие установленные версии, сохранив данные |
| `sudo rat-race status` | Посмотреть состояние служб |
| `sudo rat-race logs` | Посмотреть последние записи журнала |
| `sudo rat-race health` | Проверить доступность приложения |
| `sudo rat-race version` | Показать установленную версию |

По умолчанию команда действует на все установленные части. Для одной части добавьте `app` (приложение и бот) или `builder` (конструктор). Например: `sudo rat-race update builder`. Для просмотра журнала в реальном времени: `sudo rat-race logs app --follow`.

## Управление с Windows

Один раз установите зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-admin.txt
```

Доступы находятся в приватном `server.txt`. Для SSH в нём нужны поля ниже; адрес и пароль веб-редактора оставьте в том же файле:

```text
IP: адрес сервера
PORT: 22
USER: имя пользователя
PSW: пароль
```

Нужен root либо пользователь с sudo без запроса пароля. После установки сервера используйте те же команды:

```powershell
.\commands\server.cmd update
.\commands\server.cmd restart app
.\commands\server.cmd status
.\commands\server.cmd logs app --follow
```

## Настройки и данные

- `/etc/rat-race/` — настройки и доступы.
- `/var/lib/rat-race/` — база, игры, материалы и резервные копии.

Резервируйте оба каталога. Пароли, токены и файлы доступов не размещайте в GitHub.
