# Развёртывание «Крысиных бегов»

Разработка и тесты выполняются локально. Код передаётся через `https://github.com/aske312/tg_game`, ветка `main`. Сервер получает только закоммиченную версию из GitHub.

## Обновление

Локально:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
git add app static games tests deploy scripts README.md requirements.txt .env.example .gitignore start-local.cmd start-telegram.cmd
git commit -m "Describe the change"
git push origin main
.\.venv\Scripts\python.exe scripts/deploy_server.py
```

На сервере:

```bash
sudo bash /opt/rat-race/current/deploy/update.sh
```

Можно также запустить `deploy-server.cmd` после `git push`. Подключение берётся из локального `server.txt`; на сервер копируется версия из GitHub, а не незакоммиченные файлы компьютера.

Скрипт скачивает `main`, создаёт отдельный каталог релиза по SHA, запускает тесты, делает согласованную резервную копию SQLite и переключает `/opt/rat-race/current`. После проверки `/api/health` перезапускается бот. Предыдущие релизы сохраняются. Если новый веб-сервер не отвечает, переключается предыдущий каталог. Зависимости находятся в общей `.venv`; изменения зависимостей требуют отдельной проверки совместимости при откате.

## Постоянные файлы

- `/etc/rat-race/app.env` — токен бота, HTTPS-адрес, настройки (root:root, 600).
- `/etc/rat-race/release.env` — SHA запущенной версии.
- `/var/lib/rat-race/game.sqlite3` — база игры (служба `ratrace`).
- `/var/lib/rat-race/games/<имя>/game.json` — авторские игры и медиа рядом с документом; загрузка через SFTP, обновление списка без перезапуска.
- `/var/lib/rat-race/media/` — материалы комнат. Для полной резервной копии нужны база, этот каталог и авторские игры.
- `/var/lib/rat-race/backups/` — резервные копии перед обновлением.
- `/opt/rat-race/repo.git` — зеркало GitHub.
- `/opt/rat-race/releases/<SHA>/` — неизменяемые версии приложения.

Файлы `.env`, `server.txt`, базы и ключи SSH не передаются в GitHub. `scripts/server_admin.py` использует локальный `server.txt`; для него отдельно установите `paramiko` в локальное окружение. Формат: `IP: ...`, `PORT: 22`, `USER: ...`, `PSW: ...`.

## Диагностика

```bash
systemctl status rat-race-web rat-race-bot --no-pager
journalctl -u rat-race-web -u rat-race-bot -n 50 --no-pager
curl -fsS http://127.0.0.1:8010/api/health
systemctl status rat-race-cert-renew.timer --no-pager
sudo /opt/rat-race/.venv/bin/python /opt/rat-race/current/deploy/smoke_test.py
sudo /opt/rat-race/.venv/bin/python /opt/rat-race/current/deploy/smoke_modes.py
sudo /opt/rat-race/.venv/bin/python /opt/rat-race/current/deploy/smoke_presentation.py
```

Smoke-тест создаёт временную явно обозначенную тестовую сессию и тренировочную комнату. Через публичные HTTPS/WebSocket проверяет текстовый ответ, очки, искусственного соперника и адрес кнопки Telegram. В конце удаляет только созданные им комнату и сессию.

`smoke_modes.py` проверяет игру «Три режима — один забег» с ведущим и двумя временными игроками: переходы между режимами, выбор ячеек и права игроков, приватность ответов, автоматическую оценку двух вариантов и общий счёт. Также проверяет редактируемый «Демоквиз» с медиа. Удаляются только его тестовые комнаты и сессии.

`smoke_presentation.py` создаёт собственную временную игру и не зависит от наличия демонстрационных пакетов в библиотеке. Проверяет ведущего, игрока и веб-экран без входа в Telegram через публичные HTTPS/WebSocket, вступление сетки, бесшумный лимит реакций, паузу и восстановление таймера, выбор игроком, показ счёта раунда и синхронное завершение. Также создаёт пустую репетицию ведущего через API, добавляет вопрос, дожидается ответов трёх ботов и проверяет ручную оценку. В конце удаляет только свои тестовые комнаты и сессии.

Веб-экран доступен на том же HTTPS-адресе по пути `/display`: для подключения нужен только код комнаты. В интерфейсе ведущего есть прямая ссылка `/display?room=<код>`. Отдельный сервис или Telegram-аккаунт для экрана не требуется.

Сервер запускает один процесс приложения на loopback-порту 8010. HTTPS и WebSocket обслуживает Caddy на 443. Сертификат на IP выпускает Certbot с профилем `shortlived`; systemd-таймер проверяет продление каждые 12 часов. После продления сертификаты копируются в `/etc/rat-race/tls/` с доступом только для Caddy, затем Caddy перезагружает конфигурацию. HTTP-путь `/.well-known/acme-challenge/` используется для подтверждения владения IP.

Бот работает через long polling. Одновременно запускайте только один его экземпляр с одним токеном: локальный `start-telegram.cmd` после переноса на сервер не нужен. Проверять браузерный режим можно через `start-local.cmd`.

## Конструктор игр

Веб-конструктор запускается отдельно: HTTPS на **8443/TCP**, приложение на **127.0.0.1:8011**. У него собственный прокси Caddy с адресом управления **127.0.0.1:2020**. Используются HTTP/1.1 и HTTP/2; UDP-порты других служб не затрагиваются. Службы `rat-race-builder` и `rat-race-builder-proxy` и ссылка `/opt/rat-race/builder-current` обновляются независимо от игрового приложения. Админ-панель на 9443 сохраняет свой порт.

После коммита и отправки в GitHub:

```powershell
.\.venv\Scripts\python.exe scripts/deploy_builder.py
```

При первом запуске скрипт создаёт `/etc/rat-race/builder.env` с хешем отдельного пароля, адресом и каталогом игр. Адрес и пароль сохраняются локально в `data/builder-server-access.txt`. Код загружается только из GitHub `main`; пароль не выводится и не попадает в репозиторий. Повторный запуск сохраняет настройки и пароль.

На сервере последующие обновления можно запускать так:

```bash
sudo bash /opt/rat-race/builder-current/deploy/update_builder.sh
systemctl status rat-race-builder rat-race-builder-proxy --no-pager
curl -fsS http://127.0.0.1:8011/api/health
```

Обновление запускает тесты, проверяет свободные порты и переключает только службы конструктора. Используется существующий TLS-сертификат; после его продления перезагружаются оба прокси. Зависимости общие с основным приложением, новые зависимости в этой версии не добавлены.

Постоянные файлы конструктора:

- `/etc/rat-race/builder.env` — настройки и хеш пароля (600).
- `/etc/rat-race/builder-release.env` — SHA версии конструктора.
- `/var/lib/rat-race/builder/drafts/` — черновики и материалы.
- `/var/lib/rat-race/builder/backups/` — предыдущие документы игр и закрытые ZIP-копии удалённых игр с медиа.
- `/var/lib/rat-race/builder/sessions.sqlite3` — сессии авторов сроком 12 часов.
- `/var/lib/rat-race/games/` — опубликованные игры, общие с Mini App.
- `/var/lib/rat-race/games/.deleted/` — постоянные маркеры удалённых игр; они исключают возврат встроенных примеров после обновлений.

Для резервной копии авторских игр сохраняйте `games/` и `builder/`. Публикация проходит проверку формата, сохраняет предыдущий документ и атомарно заменяет `game.json` после подготовки медиа. Перезапуск Mini App и бота для публикации не нужен; текущие комнаты сохраняют свою версию игры.

При первом развёртывании поддержки удаления обновите основное приложение (`scripts/deploy_server.py`), затем конструктор (`scripts/deploy_builder.py`): оба сервиса должны учитывать маркеры `.deleted/`. После этого удаление через редактор не требует перезапуска служб. Черновик и опубликованная папка удаляются вместе со всеми медиа; перед этим сохраняется закрытый архив в `builder/backups/<id>/*-deleted.zip`. Медиа существующих комнат в `/var/lib/rat-race/media/` сохраняются для продолжения игры.
