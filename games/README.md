# Формат игры: game.json

Одна игра — папка с единственным документом `game.json` и необязательными медиа. Все правила и раунды описаны в JSON; YAML не используется. Рабочий пример: [example-race/game.json](example-race/game.json).

```json
{
  "schema_version": 1,
  "title": "Крысиные бега",
  "rounds": [
    {
      "id": "q1",
      "type": "question",
      "text": "Сколько будет 2 + 2?",
      "answer": "4",
      "accepted_answers": ["четыре"],
      "points": 100,
      "time_limit": 45
    },
    {
      "id": "e1",
      "type": "event",
      "title": "Сырный бонус",
      "text": "Случайный игрок получает усиление!",
      "effect": {
        "type": "random_buff",
        "target": "random_player",
        "questions": 2
      }
    }
  ]
}
```

`rounds` содержит до 100 вопросов и событий на всю игру. В пакете без `stages` они идут последовательно в одном блице. `title` — до 100 символов, необязательное `description` — до 500. Документ — до 1 МБ. `id` каждого элемента уникален, содержит латинские буквы, цифры, `_`, `-`, до 64 символов; без него используется `q` с номером элемента.

## Несколько игровых раундов

Один пакет и одна комната могут сочетать разные режимы и повторять их. `stages` задаёт порядок игровых раундов; каждый вопрос или событие в `rounds` ссылается на раунд полем `stage`. Максимум 30 раундов, в каждом нужен хотя бы один вопрос. Без `stage` элемент относится к первому раунду. Счёт и эффекты общие на всю игру.

```json
"stages": [
  {"id":"s1","type":"blitz","title":"Разминка","order":"random","auto_advance":false},
  {"id":"s2","type":"grid","title":"Выбираем тему","chooser":"winner","categories":["Космос","География"]},
  {"id":"s3","type":"binary","title":"Одно из двух","order":"sequential","auto_advance":true}
]
```

`type` — `blitz`, `grid` или `binary`. `id` уникален в `stages`, формат такой же, как у вопроса. `title` — до 100 символов. Полный пример: [mixed-rounds/game.json](mixed-rounds/game.json).

В блице и выборе из двух `order` задаёт `sequential` или `random`. Случайный порядок перемешивает вопросы один раз при создании комнаты, оставляя события на своих местах. `auto_advance: true` переводит к следующему вопросу или игровому раунду через 3 секунды после завершения проверки. По умолчанию ведущий нажимает кнопку. Автопереход не пропускает непроверенные текстовые ответы. Автоматическое продолжение после события также использует паузу 3 секунды.

В сетке `category` и `points` образуют ячейки. `chooser: "winner"` передаёт выбор первому по времени правильно ответившему после оценки всех ответов; `"host"` оставляет выбор ведущему. Первый вопрос и вопрос после раунда без верных ответов выбирает ведущий. Ведущий может выбрать самостоятельно и при настройке `winner`. Текст вопросов, решения и материалы не передаются в сетке; публикуются только категории, цены и сыгранные ячейки. События размещайте в блице или выборе из двух.

`categories` задаёт список категорий раунда с сеткой: от 1 до 100 непустых уникальных названий до 100 символов. Каждому вопросу сетки обязательно задаётся `category` из этого списка. Названия сравниваются без учёта регистра. Для старых сеток без `categories` список берётся из явно заполненных категорий вопросов. Название игры вместо категории сетки не подставляется.

В редакторе категории добавляются, переименовываются и удаляются на вкладке «Категории» выбранного раунда с сеткой. Переименование обновляет привязанные вопросы этого раунда. Удаление категории снимает привязку; черновик можно сохранить, а публикация потребует назначить категории заново. Счётчики и сводка относятся только к выбранной сетке, включая незаполненные категории и объявленные категории без вопросов. Счётчик открывает список вопросов категории. В остальных режимах настройки категорий не отображаются.

ZIP из редактора содержит `game.json` и все медиа, используемые вопросами. Удаление игры удаляет её опубликованную папку и черновик целиком, включая неиспользуемые загруженные материалы. Закрытая резервная копия остаётся в хранилище конструктора. Маркер `<GAME_PACKS_DIR>/.deleted/<id>.json` исключает игру из библиотеки и запрещает создание новых комнат и тренировок по её идентификатору, в том числе для встроенных примеров. Не удаляйте эти маркеры при обновлении сервера. Комнаты, созданные до удаления, используют свои копии вопросов и медиа.

Для вопроса в раунде `binary`:

```json
{"id":"q1","stage":"s3","type":"question","text":"Пингвины умеют летать?","choices":["Да","Нет"],"correct_choice":1,"points":100,"time_limit":20}
```

`choices` — ровно два разных непустых текста до 100 символов. `correct_choice` — индекс 0 или 1. `answer` здесь необязателен: он получается из правильного варианта. Игрок отправляет индекс кнопки; сервер проверяет его после закрытия приёма. Правильный индекс скрыт от игроков до этого момента. Верно: +стоимость; неверно: −стоимость с учётом эффектов.

## Вопрос

`type: "question"`, обязательные `text` (до 2000 символов) и `answer` (до 500), кроме формата с двумя вариантами. `points`: целое число от 0, по умолчанию 100. `time_limit`: целое число секунд от 1, по умолчанию 45. Старые диапазоны 10–1000 и 10–300 сняты. `category` обязательна в сетке; в остальных режимах необязательна. `accepted_answers` (до 20 вариантов) используется для автопроверки тренировки. Живой ведущий проверяет текстовые ответы сам.

Для медиа добавьте к вопросу:

```json
"media": {
  "type": "video",
  "file": "media/clip.mp4",
  "start": 5,
  "end": 15
}
```

`type`: `image`, `audio`, `video`. `file` — относительный путь внутри папки игры. Для аудио и видео `start`/`end` задаются в секундах; по умолчанию весь файл. Изображения: PNG/JPEG/GIF/WebP; аудио: MP3/WAV/OGG/M4A; видео: MP4/WebM. Файл до 25 МБ, суммарно до 100 МБ. Формат проверяется по содержимому. Используйте поддерживаемые браузером кодеки, например H.264 для MP4. Файлы остаются отдельными вложениями; JSON содержит ссылки на них.

Начало отрывка неотрицательное, конец должен быть позже начала; `end: null` означает до конца записи. Произвольный предел 86400 секунд снят. В редакторе доступны плеер, ползунки по длительности файла, ввод `мин:сек` или секунд, установка границ по позиции плеера и прослушивание выбранного отрывка. Таймер ответа (`time_limit`) задаётся независимо от отрывка.

## Событие

`type: "event"`, `title`, необязательный `text`, обязательный `effect`:

Необязательная `category` (до 100 символов) поддерживается в старых документах для совместимости. Редактор сохраняет это поле при открытии, но не предлагает категории для событий: события размещаются в блице или выборе из двух.

| Поле | Значения |
|---|---|
| `type` | Конкретный или случайный эффект из таблицы ниже |
| `target` | `random_player`, `all_players`, `leader` или `last_player` |
| `questions` | Положительное целое число следующих вопросов, по умолчанию 1 |

| Эффект | Настройка | Действие |
|---|---|---|
| `double_reward` | — | Двойная награда за верный ответ |
| `shield` | — | Защита от штрафа |
| `half_reward` | — | Половина награды |
| `double_penalty` | — | Двойной штраф за ошибку |
| `reward_multiplier` | `factor` ≥ 1 | Награда умножается на заданное число |
| `reward_reduction` | `factor` от 0 до 1 | Остаётся заданная доля награды; в редакторе задаётся в процентах |
| `penalty_multiplier` | `factor` ≥ 1 | Штраф умножается на заданное число |
| `bonus_points` | Целое `amount` ≥ 1 | Дополнительные очки за каждый верный ответ |
| `penalty_points` | Целое `amount` ≥ 1 | Дополнительный штраф за каждую ошибку |
| `random_buff` | — | Случайная двойная награда или защита |
| `random_debuff` | — | Случайная половина награды или двойной штраф |

В редакторе сначала выбирается положительный или отрицательный эффект, затем его вид и величина. `leader` выбирает лидера по очкам, `last_player` — последнего игрока; при ничьей выбирается один случайный игрок среди подходящих. Эффект не назначается ведущему. Старые события `random_buff`/`random_debuff` продолжают работать.

Баф случайно выбирает двойную награду за верный ответ или защиту от штрафа. Дебаф — половину награды или двойной штраф. Каждая из двух возможностей равновероятна. При `all_players` один выбранный эффект применяется ко всем. Ведущий не участвует в выборе получателя.

Событие разыгрывается один раз при открытии раунда. Результат показывается всем и сохраняется в SQLite; переподключение и перезапуск его не меняют. После события ведущий или владелец тренировки нажимает «Продолжить».

У игрока действует один эффект: новое событие заменяет прежний. Срок уменьшается после каждого закрытого вопроса, включая пропущенный. Пропуск всегда даёт 0. Половина награды округляется вниз до целых очков. После истечения срока возвращаются обычные награда и штраф.

## Загрузка

На сервере: `/var/lib/rat-race/games/my-game/game.json` и, например, `/var/lib/rat-race/games/my-game/media/clip.mp4`. Файлы должны читаться пользователем службы `ratrace`. Локально аналогично: `data/games/my-game/` (рядом с выбранной SQLite).

Сначала загрузите медиа, затем готовый `game.json`; при обновлении заменяйте документ атомарно после окончания передачи. Нажмите «Обновить список игр». Невалидная игра не попадёт в выбор; интерфейс покажет причину. Изменения используются в новых комнатах, действующие сохраняют собственную копию.
