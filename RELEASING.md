# Выпуск версии

Коммит в `main` запускает проверки, но не публикует релиз и не обновляет сервер.

1. Изменить `VERSION` и добавить раздел с этим номером в `CHANGELOG.md`.
   Исправления повышают третий номер, новые возможности — второй. Игра,
   демонстрация и редактор читают одну версию из `VERSION`.
2. Запустить тесты, создать коммит и выполнить `git push origin main`.
3. Дождаться зелёного workflow **Checks**, включая браузерные проверки.
4. В чистой рабочей копии `main` выполнить:

   ```powershell
   .\.venv\Scripts\python.exe scripts/release.py tag
   ```

   Скрипт проверяет номер, описание, чистоту рабочей копии, совпадение с
   `origin/main` и результат Checks именно для этого коммита. Затем создаёт
   и отправляет тег `v<номер>`.
5. Workflow **Release** проверяет совпадение тега с `VERSION`, повторяет все
   проверки и публикует GitHub Release с описанием из `CHANGELOG.md`.
   При ошибке проверок публикации нет: исправить проблему новой версией
   либо повторить workflow, если причиной был временный сбой окружения.
6. Дождаться опубликованного релиза, затем обновить сервер:

   ```powershell
   .\.venv\Scripts\python.exe scripts/server.py update all
   ```

   Или на сервере: `sudo rat-race update`.

Обновление выбирает последний опубликованный стабильный GitHub Release,
получает его тег, закрепляет SHA для всех компонентов и сверяет `VERSION`.
Если опубликованного релиза нет или версия не совпадает, обновление
останавливается до переключения служб. Локальные проверки, резервная копия
базы, проверка HTTPS и откат при ошибке запуска сохраняются.

В `/api/version`, `/api/health` и интерфейсе доступны номер версии и SHA сборки.
Ссылки на CSS/JS автоматически содержат версию и сборку, чтобы браузер
не использовал старый интерфейс после обновления.
